Kinmokusei v0.4.0 expands the Go-output language with more ergonomic syntax,
abstract OOP contracts, generic collection operations, and stronger diagnostics.

## Highlights

- Optional semicolons and named Go imports such as `import go { Println } from "fmt"`.
- Arrow-style functions and `main`, contextual and forward type inference,
  recursive local arrow groups, and recursive loop initializers.
- Explicit source exports, named re-exports, and export aliases preserving
  shared storage and declaration identity.
- Abstract classes/methods with concrete implementation checks, generic
  dependency injection, multi-level dispatch, and invariant method contracts.
- Result-returning callbacks and function values, explicit discard with `_`,
  and diagnostics for unused named local Result error bindings.
- Constraint intersections and composition with imported Go type sets and
  method interfaces, plus generic callback inference.
- Generic `append`, `copy`, `clear`, `delete`, `len`, `cap`, `copyArray`, and
  `viewArray`, retaining Go behavior and source class/nullability contracts.
- Scalar reference-chain constants, constant `min`/`max` and array `len`/`cap`,
  and stronger overflow, bounds, initialization-cycle, and encoding diagnostics.
- Semantic-analysis decomposition and editor navigation, inference, completion,
  and refactoring coverage for the added language constructs.

## Upgrading from v0.3.0

- A newline immediately after `return` or `throw` ends that statement. Start
  the value or its opening parenthesis on the keyword line. Keep branch labels
  on the same line as `break` or `continue`.
- Module-level `const` arrows with unnamed function types now emit Go functions,
  not assignable function variables. Use a mutable binding when storage or
  reassignment is required.
- Direct local arrows see their own binding, and consecutive arrow groups see
  peer declarations. Rename unintended shadowing; annotate unresolved recursive
  result types.
- Adding source exports makes that file opt into explicit source visibility.
  Export all names needed by importing modules.
- Use, propagate, return, or explicitly discard Result errors. Invalid numeric,
  nullable/generic contract, and cyclic initialization cases are diagnosed more
  precisely. Scalar and eligible array-length constants are not addressable;
  use `let` when runtime storage is needed.

## Compatibility and validation

Go 1.23 through Go 1.27 are supported; release binaries are built with Go 1.27.
The release includes CLI archives for Linux amd64/arm64, macOS amd64/arm64,
Windows amd64, the matching VS Code extension, and SHA-256 checksums.

Full compiler tests and independent handwritten-Go comparisons pass, alongside
race/fuzz checks, editor tests, executable documentation, and C ABI/FFI tests.
Statement coverage is 90.4%; this is code coverage, not a claim of complete Go
language compatibility. Remaining language boundaries are documented.

The pre-1.0 v0.4.x series will include compatible features and fixes in patch
releases. v0.5 is the audited Go compatibility completion milestone. Intentional
source/public API breaks require a minor release and migration notes.

and [language guide](https://puffball1567.github.io/kinmokusei/project/releases).
