# Kinmokusei v0.4.12

This patch publishes optional chaining, lazy defaults, contextual generic
function values and the completed #117 null/zero-value safety work. It also
corrects evaluation and cleanup behavior, improves compiler robustness and
preserves dependency manifest formatting. Use matching v0.4.12 compiler and
Visual Studio Code extension artifacts.

## Optional chaining, defaults and checked absence

`?.member`, `?.[index]` and `?.(arguments)` capture their receiver once and skip
the remaining unparenthesized chain, arguments and indices on absence. `??`
evaluates its fallback only when needed. Parentheses end a short-circuit chain.

```ts
class User {
  constructor(public name: string) {}
  public next: User | null = null;
}

function label(user: User | null): string {
  return user?.next?.name ?? "anonymous";
}
```

Reference results preserve nullable semantics. Scalar/record optional results
use a checked split, a lazy default or checked postfix `!`; an existing zero
value remains distinct from an absent result. Map reads and channel receives
follow the same absence policy. Unsafe-zero checked payloads require the
matching success flag, or a nil error for `Result<T>`, before use.

## Native non-null safety (#117)

- Reject raw `nil` construction of non-null source classes, interfaces and
  function types, including aliases and constrained generic forms.
- Prevent zero-filled allocation, clearing and reslicing from exposing invalid
  reference elements, including nested structs/arrays and generic alternatives.
- Check native references at callable entry and storage/result publication,
  including rest parameters, multiple results, checked assignments/declarations,
  Result forwarding/propagation, conversions and assertions.
- Validate references read from Go-owned fields, elements, mutable callbacks
  and other unproven storage. Nested/cyclic data is checked as each reference
  is accessed, preserving identity without eagerly walking an object graph.
- Apply selective checks to mixed generic bounds while preserving valid scalar
  zeros and raw Go nil alternatives. Ambiguous native/raw policies require a
  concrete type or separate uniform constraints.
- Preserve matching success proofs through conditions and switches, and
  invalidate stale proofs after writes, escapes, captures and flow joins.

Failures identify the original `.km` position, and checks survive evaluated
fixed-array `len`/`cap` operands. Raw Go and explicit nullable contracts retain
their nil semantics; an interface containing a typed nil pointer remains a
non-nil interface. Concurrent Go mutation still requires normal synchronization.

## Contextual generic function values

A destination function type can determine missing type arguments for source
and imported Go functions. Leading explicit arguments remain supported:

```ts
function identity<T>(value: T): T { return value; }
function pair<T, U>(left: T, right: U): (T, U) { return left, right; }

const f: (value: int) => int = identity;
const paired: (left: int, right: bstring) => (int, bstring) = pair<int>;
```

This works for assignments, returns, typed aggregates/fields and callbacks.
Higher-order calls can infer a declaration callback from other arguments, such
as `apply(identity, 7)` or `slices.SortFunc(values, cmp.Compare)`, without
reordering runtime evaluation. Conflicting or unresolved types and unnameable
private Go arguments produce source diagnostics. Generic instance method values
still require direct calls.

Concrete native non-null parameter/result contracts on instantiated function
values are enforced even for direct Go callers. Variadics, multiple results,
Result success/failure paths, nullable values and typed-nil interfaces/errors
retain their contracts. Editor definition, rename, signatures and source maps
remain tied to written source rather than inferred synthetic references.

## Evaluation, cleanup and compiler robustness

- Preserve earlier values before later calls or receives can mutate them,
  including callees/receivers, arguments, literals, assignment targets, compound
  updates, return values and slice bounds (#111).
- Keep `defer` inside try/catch/finally pending until the enclosing function
  exits, in reverse registration order. Preserve eager capture, variadics,
  generic/private Go arguments, panic/recover and Goexit behavior (#110).
- Preserve caller returns, Result propagation and typed exceptions through
  iterators with their own handlers, while retaining iterator cleanup (#112).
- Reuse unchanged nested-loop checks without losing exceptional paths, Task
  obligations or capture/write effects (#105).
- Diagnose excessive syntax/array nesting and expanding generic instantiation
  cycles before stack exhaustion or invalid output (#104, #106, #108).

## Dependency and C boundary improvements

Dependency edits preserve manifest comments, spacing, table/key order and line
endings, including rollback on failure (#91). Prerelease and complete Go
pseudo-versions use canonical Go version parsing/comparison; malformed pinned
identities and module-major mismatches are rejected (#90).

Outgoing C ABI schema 2 records semantic parameter/result types and exact enum
member values. Compatibility checks catch renumbered/removed enum members and
same-transport semantic changes (#96). Outgoing symbol validation and incoming
FFI helper-name isolation diagnose collisions before output (#95, #97).

## Migration from v0.4.11

Stronger checks intentionally reject programs that previously consumed absent
payloads or published nil as a non-null native reference.

```ts
function initializeUsers(): User[] {
  // Represent absence explicitly; raw nil is not a native User initializer.
  const user: User | null = null;

  // A nonempty zero-filled slice needs nullable reference elements.
  const slots = makeSlice<User | null>(3);

  // Alternatively, initialize non-null elements through appends.
  let users = makeSlice<User>(0, 3);
  users = append(users, new User("Alice"));
  return users;
}
```

Use `value ?? fallback` for absent values, `value!` only when absence is a bug,
and matching checked splits when the success/error distinction matters:

```ts
function readName(reject: boolean): string {
  const [user, err] = loadUser(reject); // loadUser returns Result<User>
  if (err !== nil) { return "anonymous"; }
  return user.name;
}
```

Reading, logging or discarding the error does not establish success. Existing
Go typed-nil interface/error behavior is preserved. Type inference must resolve
one static type; add annotations/type arguments when it cannot.

Regenerate outgoing C ABI schema 1 baselines from their original source before
comparing schema 2 output. Dependency edits do not change normal builds' offline
policy. Libraries using the new features should set
`min-kinmokusei = "0.4.12"`.

## Updating and verification

On supported Linux/macOS installations:

```sh
keika update --check
keika update --version v0.4.12
keika version
```

Windows users install the release archive manually. Install the matching VSIX
separately. Retain the bundled license and attribution materials.

Compatibility CI covers Go 1.23–1.27, Linux/macOS/Windows, race detection,
fuzzing, C ABI/FFI, editor integration and executable documentation. The new
features have independent handwritten-Go runtime comparisons, checker/editor
regressions and executable examples. Release archives are built with Go 1.27
and verified before publication.

Release assets include five CLI archives, the matching VSIX and `SHA256SUMS`.
