# Kinmokusei v0.4.11

This patch adds compiler version inventory, clearer Go boundary diagnostics and
earlier rejection of invalid nullable generic declarations. Use matching
v0.4.11 compiler and Visual Studio Code extension artifacts.

## Compiler version inventory (#147)

```sh
keika versions
keika versions --remote
keika use 0.4.11
```

Local inventory lists retained bundles, including inactive versions, with size,
receipt status and active/protected markers. It does not access the network,
execute cached compilers, change files or switch versions. Only the invoked
installation's managed cache is scanned; arbitrary manual copies elsewhere
are not discovered. Concurrent switches can change the observed state.

`--remote` explicitly fetches official stable release metadata for the current
OS and architecture. The list is paginated, deduplicated and numerically sorted;
retrieval or metadata errors do not return a partial list. Listing checks asset
metadata, not archive contents. Selecting or updating a compiler still performs
full checksum, archive, license and executable-version verification.

`keika use` accepts both `vX.Y.Z` and numeric `X.Y.Z` spellings. On Linux/macOS,
`keika-use versions` keeps inventory available after selecting an older compiler.
An existing companion needs the newer management snapshot: invoke `keika use`
from the new compiler before downgrading. Windows can list official downloads
with `--remote`; installation and version selection remain manual there.

## Verified-text Go boundary diagnostics (#99, #148)

Errors such as `cannot use *Config as any` now explain that an opaque Go
interface could expose verified UTF-8 string storage to unvalidated writes or
calls. Open generic storage gets a separate explanation that its contents
cannot be proven safe. The diagnostic recommends concrete raw `bstring` input
storage followed by checked `string(raw)` construction.

Assignment rules remain unchanged. Concrete raw/numeric DTO pointers,
immutable scalar text and copied scalar fields remain supported. Diagnostics
preserve their original prefix and source location, including forwarded
multiple results.

## Nullable generic declarations (#114, #149)

`T | null` now requires a constraint that guarantees a nil representation for
every possible instantiation. Unconstrained, scalar-mixed, comparable-only and
method-only bounds are rejected at the source declaration, even when unused,
instead of passing checking and failing generated-Go validation.

```ts
constraint Pointer = ~*int;
function orElse<T extends Pointer>(value: T | null, fallback: T): T {
  if (value === null) { return fallback; }
  return value;
}
```

Nil-capable unions and `*T | null` / `T[] | null` with arbitrary element types
remain supported. Postfix non-null assertions share the same capability rule.
Code using an unconstrained nullable parameter must add a suitable constraint
or represent presence explicitly for arbitrary scalar/struct values; this
release does not add an optional-value wrapper.

## Updating and verification

On supported Linux/macOS installations with self-update:

```sh
keika update --check
keika update --version v0.4.11
keika version
```

Windows users install the release archive manually. Install the matching VSIX
separately. Libraries relying on these changes should declare
`min-kinmokusei = "0.4.11"`.

Compatibility CI covers Go 1.23–1.27, Linux/macOS/Windows, race detection,
fuzzing, C ABI/FFI, editor integration and executable documentation. Regression
tests cover offline inventory, official release pagination and validation,
independent-manager use after downgrade, JSON decoding diagnostics, source
positions and nil-capable generic execution against independent Go code.

Release assets include five CLI archives, the matching VSIX and `SHA256SUMS`.
Retain the bundled license and attribution materials.
