# Kinmokusei v0.4.7

This patch releases the accumulated compiler and editor improvements since
v0.4.6, together with the new clockwork osmanthus documentation artwork.
Use matching v0.4.7 compiler and Visual Studio Code extension artifacts.

## Documentation artwork

The documentation home page now uses a transparent mechanical osmanthus
illustration, with matching logo, favicon and social sharing card. The image
layout supports light/dark themes and smaller screens; sharing metadata uses
a 1200 by 630 PNG.

## Language and Go interoperability

- Runtime-checked postfix `!` for nullable and raw nil-capable references:
  evaluate once, panic with the source filename/line/column on nil, or use the
  checked value through member, index and call expressions. It cannot unwrap
  `Result` or `Task`; Go interface typed-nil semantics are unchanged.
- Explicit `T | null` bindings retain nullable state when receiving raw Go
  pointers, interfaces, functions, collections and `unsafe.Pointer`. A matching
  storage type alone is not a non-null proof.
- Imported Go and native struct, enum, defined-type and interface method
  expressions with explicit receiver arguments, including instantiated aliases
  and direct `<T>`/`[T]` receiver applications.
- Fully instantiated generic function values using `function<T>` or
  `function[T]`, preserving source text/nullability and Result contracts.
- Direct source runtime-interface bounds and method-only anonymous interface
  bounds with structural matching, dependent inference and generic owner
  substitution. Compatible native values can satisfy Go method constraints
  without erasing their checked source contracts.
- Compile-time integer expressions in fixed-array lengths, including source/Go
  constants, enum/static constants and constant `len`/`cap`/`min`/`max`.

## Compiler, CLI and editor fixes

- Delay recursive Map-key and early generic-argument validation until native
  storage/method sets are ready; diagnose invalid programs instead of crashing.
- Preserve native-struct collection fields and declared C-style `for`
  initializer types, including iteration capture/address behavior.
- Preserve normal child-process exit codes in `keika run` and clean up its
  private executable. Build/launch failures retain status 1.
- Report uncaught native exception class names/messages instead of internal
  panic-wrapper pointers; isolate closure flow, captures and Task state.
- Emit versioned Go-to-`.km` source maps for compiler-managed builds and optional
  `emit-go -source-map`, with input hashes and stable source-origin IDs for
  diagnostics and coverage consumers.
- Hover directly imported Go declarations and navigate to their Go source;
  improve method-expression, generic-bound and postfix-assertion completion,
  definition/reference/rename and signature help.

## Upgrading from v0.4.6

Recheck applications and source libraries after upgrading. Explicitly nullable
Go values must be checked before use; choose a null guard for expected absence,
or postfix `!` when absence is a programming error. Stronger recursive-type,
generic and source-contract diagnostics can reject previously accepted invalid
code. Libraries using the additions should declare
`min-kinmokusei = "0.4.7"`.

The verified `string` / raw `bstring` split introduced in v0.4.6 is unchanged.
Postfix `!` checks the reference itself, not arbitrary nested Go-owned storage.
This release does not complete the broader null/zero-value safety audit.

CLI archives are provided for Linux/macOS (amd64/arm64) and Windows (amd64),
alongside the matching VSIX and `SHA256SUMS`. Preserve the bundled license and
attribution files when redistributing binaries.
