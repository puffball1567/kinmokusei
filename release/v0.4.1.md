Kinmokusei v0.4.1 adds the foundation for reusable Kinmokusei libraries:
create a package, publish a tagged version, and consume it through ordinary
imports without copying sources or editing generated Go.

## Highlights

- External `.km` packages with public entries/submodules, direct and transitive
  dependencies, exact tagged versions, integrity hashes and compatibility checks.
- `keika deps` acquisition, updates, listing, removal and lock-preserving fetch,
  with local replacements for parallel library/application development.
- Package-aware checking, execution, builds and Go emission. Normal compilation
  and editor analysis remain offline and do not change manifests or locks.
- LSP diagnostics, completion and navigation across external packages, including
  workspace context without an open consumer source file.
- `keika new app` and `keika new library`: sample code, manifests, offline locks,
  README and ignore files, with custom names, module paths and license metadata.
- Generic indexing and slicing over compatible collections, mixed arrays/slices
  and string/byte-slice constraints, retaining Go runtime and source type contracts.
- More accurate public-source dependency discovery, shared replacement handling,
  and editor support for constructor parameter fields.

## Getting started

```sh
keika new app myapp
cd myapp
keika check
keika run
```

Create a library with `keika new library --module example.com/mylib mylib`.
Choose a real repository module path and license before publishing. Library
license metadata defaults to `UNLICENSED`; license text is not generated.
See the [external package guide](https://puffball1567.github.io/kinmokusei/guide/external-packages)
for tagging, normal imports and local replacements.

## Compatibility

- Existing Go-only schema 3 locks remain readable. Explicit dependency changes
  produce schema 4; commit the lock and restore it with `keika deps fetch`.
- Source packages currently select one exact tagged version per module;
  conflicting source requirements are diagnosed rather than silently upgraded.
- Library authors targeting this package infrastructure should declare
  `min-kinmokusei = "0.4.1"` and matching module/version metadata.
- Go 1.23 through Go 1.27 are supported. Compiler archives and the matching
  VS Code extension are versioned together; release binaries use Go 1.27.

## Validation

Full regression tests pass with 90.3% statement coverage and every measured
package above 80%. Package/CLI/LSP race checks, editor tests and reproducible
VSIX packaging pass. Documentation validation includes 66 valid examples and
40 diagnostic examples. An independently developed CLI library was verified
through local replacement, compilation and execution, with package metadata
added to a test copy; its own behavioral and fuzz tests also pass.

This release follows the project's pre-1.0 policy of compatible features and
fixes in v0.4.x; v0.5 remains the audited Go compatibility milestone.
