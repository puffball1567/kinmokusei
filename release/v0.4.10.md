# Kinmokusei v0.4.10

This patch strengthens generic type contracts and adds supported adapters for
generic diagnostics, serialization and staged input binding. It also improves
generic literal inference and adds exact compiler version switching. Use
matching v0.4.10 compiler and Visual Studio Code extension artifacts.

## Contract-preserving generic class downcasts (#140)

A native `Box<bstring>` can no longer be recovered as `Box<string>` merely
because both source arguments lower to Go `string`. Checked mismatches return
`false`; forced mismatches panic instead of producing forged verified text.

Native source contract information survives generic functions, constructors,
inheritance, method values and nested arguments. Same-contract native round
trips, nominal identity and public Go signatures are retained. Arrays, other
generic arguments and nullable types keep their source distinctions too.

Go type identity or reflection is not a source-contract proof. Values made
through a direct generic Go entry point may lack native contract information;
native downcasts reject that unknown information. Use a Kinmokusei factory for
boxes that must later be recovered through native checked downcasts. Public Go
projection helpers keep their Go behavior; they are not native validators.

## Safe generic Go adapters (#138)

- Scalar-only `inspect*` operations expose type labels/identity, kind, typed
  nil, comparability, equality, floating-point values and raw text without
  exposing writable reflection views or invoking input methods.
- Direct `fmt.Sprintf` has a separately audited callback-aware contract,
  supporting generic values and deferred formatting. It returns raw text;
  unknown stored function values, `fmt.Errorf` and arbitrary writers do not
  inherit the permission.
- `jsonSnapshot(value)` and `jsonSnapshot(value, prefix, indent)` encode generic
  native values into independent bytes. Failure returns a text-only error,
  preventing reflection-bearing errors from exposing writable input aliases.
- A documented typed allocation/extraction adapter supports generic error
  handling without an unchecked `*T` assertion, including custom `As` mutations
  when the method returns false.

These are explicit capabilities, not blanket permission for reflection, JSON
decoding or opaque Go mutation. Snapshot error type, identity and unwrap chains
are intentionally not retained. Formatting/encoding callbacks have ordinary
side effects and synchronization requirements.

## Staged input construction and binding (#141)

The embedded `kinmokusei/input` source module provides:

```ts
import { decodeInput, bindInput } from "kinmokusei/input";
```

`decodeInput(read, construct)` reads a concrete raw DTO, then validates and
constructs a new native value. `bindInput(read, construct, publish)` additionally
invokes publication once after both stages succeed. A read failure skips the
later stages; a construction failure skips publication. Errors retain identity
and ordinary panics propagate.

Frameworks keep their JSON/query/URI/form selection, strict-field/trailing-value
checks and validation policies in typed adapters. Classes, structs, nullable
values and collections retain normal native construction contracts. There is
no per-DTO compiler exception or automatic permission to decode into arbitrary
verified `T` storage.

Use fresh raw staging and a final publication callback to preserve the previous
destination and its aliases on failure. This is not a transaction over arbitrary
callback side effects, captured state or partially executed publication. See
the input adapter guide for the complete aliasing contract.

## Generic literal contextualization (#137)

Explicit generic arguments and preceding typed arguments now contextualize
fresh array/object literals, including nested arrays, fixed arrays and variadic
forms. Existing shared `string[]` storage remains invariant with `bstring[]`;
the improvement does not reinterpret existing mutable storage. Numeric and
callback inference and source evaluation order are preserved.

## Exact compiler version switching

On Linux/macOS, `keika use vX.Y.Z` selects an exact official stable compiler,
including older releases. Verified cached bundles can be reused without
network; `--offline` requires such a cache. An independent `keika-use` companion
keeps switching available after selecting a compiler without the `use` command.

Downloads, checksums, full-bundle receipts, bundled notices and executable
versions are checked before switching. Changed caches and unrelated files are
not overwritten. `keika update` retains its explicit-downgrade rejection, and
normal compilation still does not contact the release service.

## Updating and compatibility

From v0.4.8 or later on supported Linux/macOS installations:

```sh
keika update --check
keika update --version v0.4.10
keika version
```

After installing v0.4.10 once, use `keika use` or `keika-use` for exact version
selection. Windows users can check availability and manually install the
release archive. The matching VSIX is installed separately. Libraries relying
on these additions should declare `min-kinmokusei = "0.4.10"`.

Recheck code that depended on an erased native downcast contract. Generic
libraries adopting the new observation, snapshot or input APIs need the
documented typed adapters; unclassified Go boundaries remain checked.

Release archives cover Linux/macOS amd64/arm64 and Windows amd64, with the VSIX
and `SHA256SUMS`. Retain bundled license and attribution materials. Compatibility
CI covers Go 1.23–1.27, Linux/macOS/Windows, race detection, fuzzing, C ABI/FFI,
independent Go comparisons and executable documentation examples.
