# Kinmokusei v0.4.3

This patch adds short imports for external Kinmokusei packages, automatically
configured when installing dependencies.

## Short imports without manual configuration

`keika deps add example.com/greeting@v0.1.0` now registers `greeting` as a
project-local import alias and updates the lock in the same transaction:

```ts
import { greet } from "greeting"
import { format } from "greeting/format"
```

- The default name is the final module-path component, ignoring a trailing
  major-version suffix such as `/v2`.
- Use `keika deps add --alias hello example.com/greeting@v0.1.0` to choose a name.
  Conflicts fail without overwriting existing project settings.
- Aliases also support re-exports and editor navigation. Each package resolves
  its own aliases; canonical dependency paths, hashes and type identity remain
  unchanged. Go-only dependencies keep their existing behavior.
- Dependency updates preserve aliases; removing a direct dependency removes
  its aliases. Existing projects can add `[imports]` entries and run
  `keika deps lock` once to enable short names for already-installed packages.

## Language and maintenance improvements

- Imported constants, variables and functions named `main` stay module-local.
  They no longer acquire executable-entry restrictions or accidentally become
  the application entry point.
- `copyArray` accepts array-constrained target type parameters, including mixed
  lengths, imported constraints and generic class methods, while preserving
  element identity and nullability checks.
- Parser and Go emission are split into responsibility-focused files without
  changing grammar or generated code.

Go 1.23–1.27 remain supported. CLI archives include the applicable Go license
and third-party notices, as introduced in v0.4.2.
