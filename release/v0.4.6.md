# Kinmokusei v0.4.6

This release adds verified UTF-8 text, expands ownership-aware C FFI for native
library bindings, and refreshes the user manual and executable examples.

**Compatibility notice:** despite its patch version, v0.4.6 intentionally changes
source and public API text contracts. Applications and external `.km` libraries
written for v0.4.5 may require migration. The previous Go-compatible string
behavior was not inherently memory-unsafe; this release adds an explicit text
validity guarantee and rejects operations that cannot preserve it.

## Verified text and raw bytes

- `string` is immutable valid UTF-8 in checked Kinmokusei code. `bstring` stores
  arbitrary immutable bytes; `b"\xff\x00"` is a raw byte-string literal.
- `string(raw)` for `bstring` or byte-slice input returns `Result<string>`.
  Invalid UTF-8 produces an error rather than replacement characters. Byte-slice
  conversion copies a snapshot instead of sharing mutable storage.
- Verified-text slices reject bounds that split a UTF-8 code point. Raw
  `bstring` slicing retains byte-oriented Go behavior.
- Preserve text contracts across aliases, named types, generics, callbacks,
  shared storage, source interfaces and hidden implementation fields. Go
  reflection/opaque interface escapes cannot erase a verified-text contract.

## Migrating from v0.4.5

Use `bstring` for runtime Go strings, shared Go string collections, callback
inputs and raw error messages. Scalar verified text can widen to `bstring`
without copying, but raw data needs checked decoding to become `string`:

```ts
function decode(raw: bstring): Result<string> {
  return string(raw);
}

function appendText(raw: bstring): Result<string> {
  const text = string(raw)?;
  return ok(text + "!");
}
```

Alternatively, split `[text, err]` and handle the error explicitly. Go interface
assertions are type checks, not UTF-8 validation: assert raw storage, then decode.
For arbitrary byte offsets, slice `bstring(text)` rather than verified text.

`Response.text()` now returns `Result<string>`. Use `rawText()` when raw response
bytes are intended. `Exception.message` and `.error()` are `bstring`. Native
Kinmokusei generic text constraints use `~string`; raw Go-compatible text uses
`~bstring`. Shared `string[]` and `bstring[]` are not interchangeable views.

Generated Go still represents both contracts with Go `string`. External Go
callers must honor verified-text parameters and storage, or use a raw-data facade
with checked decoding. Explicit unsafe memory operations are outside this
guarantee. Libraries relying on new behavior should declare
`min-kinmokusei = "0.4.6"` and publish migrated dependency versions.

## Incoming C FFI

- Typed `borrowedArray` inputs copy scalar, enum or POD elements to C memory for
  a call. Registration-owned `retainedArray` inputs keep copied data alive until
  their registration closes, with transactional failure cleanup.
- Multiple opaque handle arguments use stable, deduplicated locking and
  registration leases. Copied handle/registration values cannot close the
  original resources.
- `mainThread` policy pins startup to the process main thread in normal Go
  executables and returns errors for wrong-thread calls.
- Multiple call-scoped callbacks, subscription-only manifests and copied/mutable
  typed callback arrays preserve independent failure reporting and lifetimes.
- Check allocation bounds and C/Go layouts for arrays. Contain callback panics,
  including legacy `panic(nil)`, and isolate generated parameter names while
  preserving original manifest names in diagnostics.
- Verify offline distribution/build of C-backed source packages using separately
  versioned cgo Go dependencies. C strings imported through generated bindings
  are raw `bstring`; C manifest names and generated Go signatures are unchanged.

## Application notices and documentation

`keika build -o app` now writes `app-licenses/` instead of `app.licenses/`.
Existing legacy directories are left untouched. Distribute the newly generated
directory with the matching executable; attribution collection remains offline
and is not a legal-compliance certification.

The manual, type/built-in/FFI references, migration guidance and executable
examples now describe this release, including constructor/property/decorator
contracts, source packages, verified text and raw Go boundaries.

Use matching v0.4.6 compiler and editor releases. CLI archives are available for
Linux/macOS (amd64/arm64) and Windows (amd64), with the VS Code extension and
`SHA256SUMS`.
