# Kinmokusei v0.4.4

This release expands object-oriented programming and framework integration,
adds source multiple results and import aliases, and strengthens Go-compatible
evaluation, nullable contracts and Task ownership checks.

## Object-oriented programming

- Instance and static getter/setter properties with separate read/write visibility.
- Interface property contracts, generic inheritance, abstract/virtual accessors,
  explicit and final overrides, and checked dependency-injection contracts.
- Mutable static fields and typed `static const` members with inherited visibility,
  shared generic-independent storage and initialization-cycle diagnostics.
- Field initializers may read earlier initialized and accessible inherited fields.

## Decorator foundations

- Typed decorators on classes, fields, methods, accessors, constructors and parameters.
- Deterministic metadata registration across modules, canonical type identities,
  and checked value boxing/extraction.
- Checked constructor, instance/static method and accessor invocation, including
  variadics, virtual dispatch, Result failures and individually typed multiple results.

These are language facilities for external DI and routing libraries, not built-in
framework APIs. Open generic consumers do not supply concrete DI keys; concrete
generic construction/invocation adapters remain limited. Private members are not
exposed through public invocation adapters.

## Source syntax and Go interoperability

- Multiple-result declarations such as `function pair(): (int, string)`, explicit
  `return a, b`, forwarding, arrow inference and try/catch/finally returns.
- Sole-call argument expansion such as `consume(produce())`, including generic
  calls, Task launches and supported collection/numeric/unsafe built-ins.
- Method-only anonymous types such as `interface { read(offset: int): string; }`.
- Local import aliases: `import { Item as LocalItem }` and
  `import go { Sprint as render }`.
- `make[T](...)` for concrete, named and constrained slices, maps and channels.
- Broader generic inference through named collections and callback result lists.
- Target-aware integer, shift, switch and permitted unsafe layout constant checks.

## Correctness and safety

- Nullable contracts survive conversions, assignments, generic inheritance,
  callbacks and collection operations. Short-circuit conditions retain path-specific
  facts without reusing proofs invalidated by mutation.
- Task ownership is checked at Result propagation, returns, goto, labeled branches,
  loop updates and select operands. Correct callback scopes and safe paths remain valid.
- For-loop updates include continue edges. Select evaluates all channel/send
  operands before checking any body, while receive assignment targets remain lazy.
- Source aliases and generated Go names cannot silently capture unrelated locals.
- External packages reject source paths through unhashed metadata directories;
  LSP framing rejects oversized headers and duplicate Content-Length fields.
- Editor completion, navigation, rename and diagnostics cover the new constructs,
  including recovery while typing incomplete member expressions.

## Compatibility and upgrading

- This is a pre-1.0 feature-bearing patch release under the documented v0.4.x policy.
  It does not claim complete Go language coverage or completion of the v0.5 audit.
- Upgrade the compiler and VS Code extension together. Packages requiring these
  features should declare `min-kinmokusei = "0.4.4"`.
- Stronger checks may newly reject invalid programs: handle each Task exactly once
  on every relevant path, check nullable values before use, and explicitly discard
  unused conversion/value-only builtin results with `_ = ...` when intentional.
- Source result lists are not general tuple storage. Named results and multiple-result
  properties remain unsupported. Static fields/accessors do not capture class type
  parameters, and static storage is shared across generic instantiations.
- Go 1.23–1.27 remains the supported toolchain range. Generated Go remains standalone.
  CLI archives include third-party attribution materials; retain these when redistributing.

## Verification and downloads

The implemented runtime registry contains 103 contract groups backed by isolated
handwritten-Go comparisons. Complementary tests cover rejected programs, editor
protocols, race behavior, fuzz inputs, C interoperability and executable documentation.
This count describes implemented contracts, not the percentage of all Go features.

Release assets contain CLI archives for Linux and macOS (amd64/arm64), Windows
(amd64), the matching VS Code extension, and `SHA256SUMS`.
